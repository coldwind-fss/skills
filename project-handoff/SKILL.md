# 项目交接

创建交接内容；不要继续实施、部署、编辑文件或更改外部状态。仅在有必要区分事实与假设时进行有针对性的只读检查。交接内容必须足以让新助手安全地定位并使用现有部署设置，而无需从头重新摸索。

## 收集事实

将对话作为主要来源。仅检查验证重要事实所需的当前工作区、测试输出、部署脚本或服务状态。绝不暴露密钥、令牌、Cookie、私钥或完整的环境变量值。

将事实分为：

- 已完成且已部署；
- 已完成但未部署；
- 未完成或受阻；
- 风险及仍需用户验证的事项；
- 本地与生产环境的差异。

将任何未经确认的信息标记为 **待核实**。不要推断服务器路径、服务名称、提交哈希或测试结果。

### 部署延续性清单

对于已经部署或工作区中包含部署材料的项目，在撰写交接内容前进行有针对性的只读清点。记录每一项已确认的事实，或将其标记为 **待核实**；不要因某项值敏感而悄然省略某个类别。

- 已知时的云服务商上下文和生产 URL。
- 已确认时的远程连接方式（例如 SSH/SCP），以及选择目标所需的非敏感目标元数据（主机别名或地址、端口、用户和远程应用目录）。
- 部署配置、部署脚本和 SSH 身份文件引用的本地绝对路径。若配置文件包含凭据，仅说明其路径和相关字段名；绝不打印其内容、密钥值、私钥材料、令牌、Cookie 或完整环境变量值。
- 服务/进程管理器、确切的进程名称、运行时路径/版本、已知时的反向代理或本地监听地址/端口，以及不得触碰的服务。
- 当前部署标识：最新备份目录、最新静态资源/缓存版本、最近上传的文件、重启范围，以及最后一次已验证的服务/公共端点状态。
- 安全的、项目特定的部署顺序及其禁止事项。应通过配置的本地路径引用配置，而非用猜测的连接参数替代它。

当继续工作需要私钥或连接详情，但其无法安全地出现在提示词中时，写明：`连接资料已保存在 <绝对路径>，新助手须在本机读取，不得在聊天中输出。` 这并非省略该路径的理由。

## 输出

用中文返回以下两项交付物。

### 1. 当前状态摘要

控制在最多 10 行。先说明当前可用内容，再陈述下一项优先事项及任何阻碍。

### 2. 项目迁移提示词

在一个围栏式代码块中放入一条自包含的提示词。它必须以以下内容开头：

`继续维护现有项目，不要重新搭建；先审计代码、现有改动、测试和部署脚本，再执行未完成任务。`

仅包含对下一位助手有用的信息：

- 项目名称、绝对路径、用途、重要测试数据路径；
- 一个包含上述部署延续性清单的 `部署与连接资料` 小节；
- 可能引发回归的架构与业务规则；
- 最近修改的文件及每项相关修改的原因；
- 相关时提供测试命令、结果、缓存及付费/外部 API 调用次数；
- 部署流程、备份、当前服务状态和冒烟测试结果；
- 按优先级排序的明确当前任务列表；
- 下一位助手必须进行的首次检查。

以 `迁移时需要用户重新提供的信息` 结尾；若没有缺失信息则写 `无`。

## 质量标准

删除重复讨论和探索过程中的死胡同。保留决策、已验证的根本原因、兼容性约束、回滚/备份位置和未解决的问题。说明下一位助手不得盲目回退现有更改，也不得重复付费 API 调用。若缺少部署清单，或缺少解释该清单为何不适用的明确 `未部署/待核实` 声明，则交接内容不完整。除非用户明确要求，否则在生成交接内容后不要再加入继续工作的指示。
