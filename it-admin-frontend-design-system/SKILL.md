# IT 后台前端设计体系

把「IT 项目协作空间」的视觉和布局经验用于其他后台系统。以 2026-09-22 本地源码为依据，保留紧凑、清楚、适合中文业务操作的风格。此包可独立使用，不依赖原工程路径或生产服务。

## 使用方式

先看目标项目的框架、现有主题和用户要改的页面。完整新建时使用本包的技术基线和模板；局部调整时只提取需要的视觉模式；用户已有 React、组件库或不同构建工具时，用原栈表达同一套视觉规范，不为套用 Skill 迁移框架。

按任务阅读：

- 布局、依赖和接入：读 [技术与布局](references/architecture.md)。
- 配色、字体、密度、间距、阴影、动效：读 [设计令牌](references/design-tokens.md)。
- 选择组件、复用原组件、设计业务页面：读 [组件与页面目录](references/components.md)。其中覆盖原工程全部 13 个独立组件及内联 UI 模式。
- 写 CSS、表单、表格、弹层和交互状态：读 [实施配方](references/recipes.md)，按需使用 `assets/`。

## 保留的视觉特征

深靛蓝导航 `#1a1f36` + 白色 64px 顶栏 + 浅灰 `#f9fafb` 内容画布。主操作使用 `accent-500 #3b82f6`，不要误把 `primary-500 #556699` 当成按钮蓝。桌面侧栏宽 208px，主体占满可用宽度，浅边框与小圆角组织高密度信息。

标题、正文、说明和元数据有明显层次；主内容常用 12–14px。原工程部分表格元数据为 10–11px，只在密集次要信息中复用；面向业务填写的正文和字段保持容易阅读。白色卡片、灰色边界为主，状态色用于标签、提示、分组和少量数值。

按页面目的选择一个主体：表格用于比较，列表加详情用于处理记录，详情页用于理解单个对象，业务入口用于提交及追踪。采用同一视觉体系不意味着每页都要增加统计卡、待办栏或额外工作台。

## 实施要点

1. 根据任务选页面骨架、信息密度和组件；将目标业务数据映射到组件，保留其权限、字段含义和操作语义。
2. 复用主题和样式。`assets/tailwind.preset.cjs` 是 Tailwind 3 预设；`assets/admin-ui.css` 包含原有全局组件类及标明来源的通用补充。
3. 新建壳层时可用 `assets/AdminShell.vue`。需要可运行的视觉参考时用 `assets/AdminUiExample.vue`；示例数据仅在内存中操作。
4. 避免溢出：flex/grid 收缩节点保留 `min-w-0 min-h-0`，明确滚动容器；宽表在表格区域滚动。业务外部表单单独使用自然页面滚动。
5. 保留加载、空态、错误、选中、只读和保存中状态；按钮点击后应有可见结果。状态不要仅靠颜色表达。
6. 用目标项目的构建与类型检查验证实现，并检查长中文标题、窄窗口、表格溢出和弹层遮挡。仅编译通过时，不声称已完成浏览器视觉验证。

源系统的 L2/L3、实名权限、通知、接口和部署路径属于业务实现，不作为其他系统的默认设置。原组件中已有的密度不一致、旧状态配色和无障碍缺口在参考文档中明确注明，不应被当作必须复制的设计要求。

## 资源校验

`node scripts/check-assets.cjs --project <装有本包技术基线依赖的项目目录>` 可以在内存中编译样式及 Vue 模板、检查本包链接，并验证颜色及字体预设。它只读取目标项目的依赖，不安装包、不修改目标工程、不调用 API。
